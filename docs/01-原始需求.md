> 本文为用户最初描述的需求原文与结构化整理，后续所有设计应可追溯至此文档。

## 1. 用户原文

> 帮我生成一个项目 007-docs-moyu，用于前期的我一个项目的设计工作。
>
> 这个项目我主要是想完成这么一个事情：搭建一个个人桌面端的应用程序。这个程序是一个平台框架，
> 用户可以在上面通过对话的形式创建智能体（AI 生成，但是怎么创建智能体呢），
> 我们平台要提供一个元智能体，就是可以创建智能体的智能体。创建完成的智能体可以进行在平台上进行使用（这很重要）。
> 每个智能体可能聚合联合使用多个 AI，比如有生图的 AI，有写文档的 AI 等等。
> 当然智能体还有比如说记忆、调用工具集成、SKILL、MCP 配置等等。都可以通过对话生成。
>
> 然后每个智能体还要有可用模型选择，比如有的简单的智能体可以通过使用简单便宜的模型就可以完成工作，有的智能体就不行，要有动态切换（这块听下来好像需要一个监控智能体）。
> 智能体运行时还要有沙箱。
>
> 其实：总体需求就是：通过以完成一项事情为维度。比如写一份标书、从教学 PDF 中抽取内容生成 PPT 等各个智能体。要能在平台上能生成出来、并且能运行自行出结果。
>
> 架构大概是：其实就是 一个框架（智能体管理、智能体沙箱执行）、几个基础智能体、自定义业务智能体。

## 2. 关键需求点（结构化拆解）

### 2.1 产品形态
- **桌面端应用程序**（个人使用）
- **平台型**产品（提供框架，承载多个智能体）

### 2.2 核心机制：通过对话创建智能体
- 提供一个**元智能体（Meta-Agent）**
- 用户与元智能体对话，描述需求 → 元智能体生成一个新的"业务智能体"
- 创建出的智能体**配置**也可通过对话生成，包括：
  - **记忆**（Memory）
  - **工具集成**（Tools）
  - **SKILL**
  - **MCP 配置**
- 业务智能体生成后必须能**在平台上直接被使用**（不是仅产出配置文件）

### 2.3 智能体能力组合
- 一个智能体可能**聚合多个 AI 能力**：
  - 文生图
  - 写文档
  - （隐含）数据分析、代码、语音等
- 各能力组合协作完成单个任务

### 2.4 模型选择与动态路由
- 每个智能体可指定**可用模型清单**
- 简单任务 → 便宜/小模型
- 复杂任务 → 强模型
- 需要**动态切换**机制
- 用户提到需要一个**监控智能体**来辅助这个决策

### 2.5 运行时隔离
- 智能体运行需要**沙箱**

### 2.6 任务维度
- 以"完成一件事"为颗粒度
- 示例任务：
  - 写一份标书
  - 从教学 PDF 抽取内容生成 PPT

### 2.7 架构骨架（用户构想）
1. **框架层**：智能体管理 + 智能体沙箱执行
2. **基础智能体**：平台预置（含元智能体、监控智能体等）
3. **自定义业务智能体**：用户通过元智能体对话生成

## 3. 隐含/未明确的点（需后续与用户对齐）

| # | 待澄清问题 | 影响范围 |
| --- | --- | --- |
| Q1 | 仅个人使用 还是 也考虑多人/团队？ | 架构复杂度、是否需要账号体系 |
| Q2 | 是否完全本地运行？模型走云 API 还是本地模型？ | 性能、隐私、成本 |
| Q3 | 沙箱级别：仅 Python 代码隔离？还是需要完整文件系统/网络隔离？ | 技术选型（venv / Docker / WASM） |
| Q4 | "对话生成智能体"输出的是配置（JSON/YAML）还是代码？ | 元智能体复杂度 |
| Q5 | MCP 是否一定要支持？还是先做内置工具？ | 第一版范围 |
| Q6 | 监控智能体是常驻进程还是按需触发？ | 资源消耗 |
| Q7 | 是否需要持久化对话/任务历史？跨会话记忆怎么管理？ | 存储设计 |
| Q8 | 是否打算未来开源/产品化？ | License、架构开放度 |
