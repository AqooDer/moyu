# 19. 产品定位与界面方案调整

> 状态：v0.1 设计决策  
> 日期：2026-05-26  
> 背景：基于 9 张 UI 概念图与当前 Runtime / Artifact 原型结果，对 Moyu 的产品定位和界面方案做收敛。

## 1. 核心结论

Moyu 不应被定位为“节点画布优先”的低代码工作流工具。

Moyu 的主定位应是：

1. **智能体创建平台**：帮助用户创建、组织、调试、发布本地 Agent。
2. **智能体运行平台**：帮助用户运行 Agent，查看 Run、Step、Trace、Artifact、日志与结果。
3. **代码驱动的 Agent 平台**：Agent 内部编排以代码、Manifest、Skill、Recipe 为主，而不是以拖拽节点作为主表达方式。

画布可以作为未来的“可视化观察/调试视图”，但不应成为 MVP 的主创建方式。

## 2. 为什么不以工作流画布为主

当前生成的 canvas 方案视觉完成度不错，但它会传递一个错误心智：Moyu 是类似 n8n / ComfyUI 的节点编排产品。

这与 Moyu 的真实方向不一致：

- Agent 的能力组合主要由代码表达，便于版本控制、测试、复用和审查。
- 平台价值在于运行时、Trace、Artifact、权限、热加载、调试闭环，而不是让用户拖线搭流程。
- 如果把画布放到第一屏，用户会自然期待节点编辑、连线、拖拽、参数面板、图布局、节点运行语义，这会显著扩大 MVP 范围。
- 画布会稀释“Agent 创建平台 + Agent 运行平台”的定位。

因此，画布降级为可选视图：

- v0.1 不做画布编辑器。
- v0.2 以后可以做“Agent 内部执行图 / Trace DAG 可视化”。
- 如果未来支持可视化 Recipe，画布也只是 Recipe 的一种表达，而不是 Agent 的唯一表达。

## 3. 推荐采用的主界面方向

9 张概念图中，最适合 Moyu 当前阶段的是：

**主方向：workbench-03 的三栏桌面应用骨架，但不沿用“中心产物预览为主”的信息架构。**

文件：

```text
artifacts/ui-concepts/workbench-03/image-01.png
```

可继承的部分：

- 左侧是 Agent Library，符合“智能体创建与管理平台”。
- 右侧是 Run Trace、Input、Output、Metadata，和当前 Runtime 数据结构高度一致。
- 底部 Artifact 区域清晰，能自然承接已实现的 `artifact list/show/open`。
- 没有把节点画布作为核心心智，产品边界更稳。

需要修正的部分：

- 中间不应以“当前输出预览”为主，而应以“任务会话 Conversation”为主。
- Artifact 是 Work 的产物集合，不是 Workbench 第一屏的中心对象。
- 左右栏需要支持收起，类似 Codex / IDE 的工作台体验。
- 左侧不应只放 Agent Library，也应放当前 Work / 任务会话列表。
- Workspace 是本地数据边界，不是高频业务分组；主界面中应弱化。

详细修正见 `20-任务会话式Workbench与多产物架构调整.md`。

辅助参考：

- **workbench-02**：适合作为运行调试视图参考，右侧 Trace 和 Local Sandbox 信息较好。
- **artifact-detail-02**：适合作为 Artifact 详情页参考，验证、溯源、元数据结构比较完整。
- **canvas 系列**：暂不作为主方向，只保留给未来 Trace DAG / Recipe 可视化。

## 4. 新的信息架构

Moyu MVP 的主导航建议为：

```text
Moyu
├── Workbench        # 运行与调试当前 Agent
├── Agents           # Agent 创建、Manifest、Skill、Recipe、版本
├── Runs             # Run 历史、Step、Trace、日志
├── Artifacts        # 产物库、预览、打开、导出
├── Models           # Provider、模型、路由、Key 状态
└── Settings         # 本地目录、沙箱、权限、运行时配置
```

## 5. 核心页面

### 5.1 Workbench

Workbench 是第一屏，也是 MVP 主页面。

布局：

- 左侧：可收起的 Work / Agent 面板
- 中间：当前 Work 的 Conversation，对话、计划、执行进度、检查点和产物卡片都进入对话流
- 右侧：可收起的 Inspector，按 Tab 查看 Artifacts / Trace / Context / Details

Run Inspector 包含：

- Run 状态
- Step timeline
- Input / Output
- Trace 文件
- 当前 Work 的 Artifact 树与 Artifact 元数据
- 错误信息与重试入口

### 5.2 Agent Detail

用于创建和维护 Agent。

建议标签：

- Overview
- Manifest
- Skills
- Recipes
- UI Schema
- Permissions
- History

这里可以提供代码文件入口，但不做复杂可视化流程编辑。

### 5.3 Run Detail

用于复盘一次执行。

内容：

- Run metadata
- Step timeline
- Logs
- Trace JSON
- Artifacts
- Re-run / Copy command

### 5.4 Artifact Detail

参考 `artifact-detail-02`。

内容：

- 大预览
- Metadata
- SHA256 / size / path
- Trace provenance
- Producing step
- Open / Reveal / Export Trace Bundle / Regenerate

## 6. 架构调整

原先容易被理解成：

```text
User -> Workflow Canvas -> Nodes -> Runtime -> Artifacts
```

调整后应为：

```text
User
  -> Agent Studio
      -> Agent Folder
          -> manifest.yaml
          -> skills/
          -> recipes/
          -> ui.yaml
          -> code
  -> Runtime
      -> Work
      -> Conversation
      -> Run
      -> Step
      -> Trace
      -> Artifact
  -> Workbench / Inspector
      -> Run history
      -> Artifact preview
      -> Debug and rerun
```

关键原则：

- **Agent 是代码资产**，不是画布资产。
- **Work 是用户目标和对话上下文**，是 Run / Artifact 的业务归属。
- **Manifest 是平台契约**，描述 Agent 能力、权限、入口、UI。
- **Runtime 是执行事实来源**，记录 Run / Step / Artifact。
- **UI 是观察和操作层**，不替代 Agent 的代码定义。
- **Conversation 是用户与 Agent 协作的主线**，Artifact 和 Trace 是它的旁路结果与证据。
- **Canvas 只做观察和辅助理解**，不作为 MVP 的核心创建路径。

## 7. MVP 开发顺序

推荐顺序：

1. 定义 Work / Conversation 数据模型
2. Workbench 静态原型改为“对话中心 + 可折叠左右栏”
3. Agent Library + 选择 Agent
4. Agent Run 表单接入现有 CLI/runtime，并把 Run 挂到 Work 下
5. Run / Step 事件进入 Conversation
6. 右侧 Inspector 可视化当前 Work 的 Artifacts / Trace / Context / Details
7. Artifact detail
8. Agent detail：Manifest / Skills / UI Schema 只读展示
9. Agent 创建向导：生成 Agent folder 模板
10. Trace DAG 只读可视化（可选）

暂缓：

- 节点画布编辑器
- 拖拽连线编排
- 复杂 no-code 参数面板
- 多 Agent 图形编排

## 8. 设计基调

Moyu 应该像一个“本地 Agent IDE + 运行控制台”，而不是 SaaS 营销后台。

风格关键词：

- local-first
- developer-friendly
- agent studio
- run inspector
- artifact library
- traceable
- code-defined
- compact but calm

视觉建议：

- 采用 workbench-03 的整体布局。
- 引入 artifact-detail-02 的 Artifact 验证和元数据结构。
- 仅在 Logo、空状态、小图标中使用墨鱼/墨迹意象。
- 不使用大面积插画、营销 hero、节点画布作为第一屏。

## 9. 国际化策略

Moyu 的界面默认使用中文。

v0.1 起至少支持：

- `zh-CN`：默认语言
- `en`：英文界面

约束：

- 所有新增 UI 文案必须走统一 key，不直接散落在组件里。
- 中文文案优先完成，再补英文。
- 设置页需要提供语言切换入口。
- 首屏 Workbench 顶栏可以保留轻量语言切换，便于原型验证。
- Agent / Run / Artifact 等平台核心术语暂不强行翻译为生硬中文，可采用“中文说明 + 英文术语”的方式，例如“运行记录 Runs”“产物 Artifacts”。
