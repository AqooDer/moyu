# 08 - 竞品与参考

> 选型不是抄，而是知道边界在哪。本文盘点同领域主流方案，明确 Moyu 的差异化定位。
> 撰写日期：2026-05-20

---

## 1. 竞品全景图

按"是否本地优先 × 是否多 Agent" 划分四象限：

```
                    多 Agent / 编排
                          ▲
       AutoGen, CrewAI    │   Dify, Coze
       LangGraph          │   n8n + AI
                          │
   ────────────────────────────────────────►
        本地优先          │   云优先
                          │
       Cherry Studio      │   LobeChat (云版)
       Ollama UI          │   Claude.ai
       Jan, Msty          │
                          ▼
                    单 Agent / 聊天
```

**Moyu 目标位置**：左上象限——**本地优先 + 多 Agent + 任务导向**。这个位置现在相对空。

## 2. 重点竞品对比

### 2.1 Dify
- **定位**：开源 LLMOps 平台，云 + 自托管。
- **创建方式**：低代码可视化编排（拖拽节点） + Prompt 设计 + RAG 配置。
- **多 Agent**：支持，但偏"工作流"而非"自主 Agent"。
- **沙箱**：Code 节点跑在受限 Python 沙箱（Pyodide / 远程 sandbox）。
- **模型路由**：手动指定，无动态切换。
- **MCP**：v0.x 已部分支持。
- **目标用户**：开发者 + 企业。
- **借鉴**：流程编排 UX、RAG 检索流水线设计。
- **不学**：Web UI 复杂度高、依赖 Python/Docker、上手成本不适合"个人工具"定位。

### 2.2 Coze（字节）
- **定位**：商业化 Agent 平台，国内主流。
- **创建方式**：表单 + 插件市场 + Bot Studio。
- **多 Agent**：v2.0 支持。
- **沙箱**：云端托管。
- **模型路由**：内部黑盒。
- **MCP**：暂无明确公开支持。
- **目标用户**：内容创作者 + 企业。
- **借鉴**：插件市场的分发机制、"以一个 Bot 完成一件事"的产品叙事。
- **不学**：纯云、强账号绑定、私有协议。

### 2.3 Cherry Studio
- **定位**：开源桌面 LLM 客户端（Electron），中国开发者主力。
- **创建方式**：表单配置 Assistant（System Prompt + 知识库）。
- **多 Agent**：弱，主要是单 Assistant 切换。
- **沙箱**：无。
- **模型路由**：手动选模型。
- **MCP**：已支持。
- **目标用户**：个人重度用户。
- **借鉴**：桌面 UX、多 Provider 管理、本地知识库、活跃的中文社区。
- **不学**：以聊天框为中心的产品形态——和 Moyu "任务导向"思路不同。

### 2.4 LobeChat
- **定位**：开源 ChatGPT-like Web App（也有桌面版）。
- **创建方式**：Agent 市场 + 表单。
- **多 Agent**：单 Agent 切换，无自主编排。
- **沙箱**：插件级，弱。
- **模型路由**：手动 + 简单规则（如长上下文自动换）。
- **MCP**：实验中。
- **借鉴**：精美 UI、插件生态。
- **不学**：Web 优先架构、个人任务执行能力弱。

### 2.5 AutoGen（微软）
- **定位**：多 Agent 对话框架（Python 库）。
- **创建方式**：代码编排（每个 Agent 是 Python 对象）。
- **多 Agent**：核心卖点，Agents 之间对话。
- **沙箱**：靠用户自己挂 Docker。
- **模型路由**：代码内手动。
- **目标用户**：研究者 + 开发者。
- **借鉴**：多 Agent 通信范式、对话即编排的思路。
- **不学**：纯代码、无 UI、无 Runtime/沙箱平台支撑。

### 2.6 CrewAI
- **定位**：多 Agent 编排框架（Python）。
- **创建方式**：声明式定义 Agent + Task + Crew。
- **多 Agent**：核心，按"角色 + 任务 + 流程"建模。
- **沙箱**：弱。
- **模型路由**：基于角色绑定。
- **借鉴**：**"角色 / 任务 / 流程"三段式建模** —— 与 Moyu 的"Recipe / Agent / Workflow" 思路相通。
- **不学**：Python 生态、纯代码。

### 2.7 LangGraph（LangChain）
- **定位**：基于状态图的 Agent 编排库（Python，TS 版较新）。
- **创建方式**：代码 + 可视化（LangGraph Studio）。
- **多 Agent**：支持子图、Human-in-loop。
- **借鉴**：**状态机 + 检查点 + 时间旅行调试**——直接影响 Moyu 的 Trace/回放设计。
- **不学**：Python 强势；TS 版生态弱；学习曲线陡。

### 2.8 n8n / Make + AI
- **定位**：通用自动化平台，近年加入 AI 节点。
- **创建方式**：可视化拖拽。
- **借鉴**：触发器机制（定时、Webhook）、连接器思路（之后给 Moyu 加"被外部触发"用）。
- **不学**：不是 Agent 优先，AI 只是节点之一。

### 2.9 Ollama + Open WebUI
- **定位**：本地模型推理 + Web UI。
- **创建方式**：模型管理 + 简单 Prompt 配置。
- **借鉴**：本地模型管理、Modelfile 概念。
- **不学**：纯单 Agent，定位与 Moyu 不重合（但 Moyu 可把 Ollama 作为本地 Provider 集成）。

### 2.10 Claude Code / Cursor / Continue
- **定位**：编程 Agent。
- **借鉴**：Tool Use 的最佳实践、Plan 模式、Skill 概念（Claude Code 的 Skill 灵感与本文 Skill 同源）。

### 2.11 Yuxi
- **定位**：融合 RAG 与知识图谱的智能体 Harness 平台，强调知识库、知识图谱、Skills、MCP、Tools、子智能体、沙盒文件系统、中间件和异步 Worker 的统一装配。
- **创建方式**：管理员配置底座，用户通过类 ChatGPT 界面与可挂载能力的智能体对话。
- **借鉴**：把模型、知识库、Skill、Tool、MCP 统一呈现为 Agent 运行上下文，帮助用户理解“这个 Agent 实际带了哪些能力”。
- **不学**：多租户/部门权限、PostgreSQL/Redis/MinIO/Milvus/Neo4j 等重依赖、知识图谱全家桶和企业级部署复杂度；这些会偏离 Moyu 的本地优先、单人维护、低上手成本定位。

## 4. Moyu 的差异化定位

凝练成一句话：

> **Moyu = 一个"以完成一件事为颗粒度"的本地多 Agent 平台，让非程序员通过对话造出能干活的 Agent。**

四个差异点（任意一个去掉就不再独特）：

1. **任务导向**（不是聊天框）
   - 入口是"我要写一份标书"，不是"我要和 GPT 聊天"
   - 产品视图是 Task / Run / Artifact，不是 Conversation
   - 适合做"长时间、有产出"的工作

2. **元智能体造智能体**（不是低代码拖拽）
   - 用户的认知模型是"和一个会做 Agent 的助手说话"
   - 低代码节点编排（Dify 路线）面向开发者；对话面向更广

3. **本地优先**（不是云）
   - 数据全本地、Key 自带
   - 离线也能用本地模型（Ollama）
   - 隐私 + 合规默认友好

4. **运行时分级沙箱**（不是无隔离也不是必装 Docker）
   - L0/L1 让 90% 用户开箱即用
   - L2 给重度用户解锁外部 CLI、网络
   - 安全模型显式、可见

## 5. 可借鉴的最佳实践清单

| 来源 | 借鉴点 | 如何在 Moyu 落地 |
| --- | --- | --- |
| LangGraph | 状态图 + 检查点 + 时间旅行 | Run 状态机 + Trace 回放（见 `06`） |
| CrewAI | 角色/任务/流程三段式 | Recipe / Agent / Workflow 三段式 |
| Dify | RAG 流水线、知识库 UX | Semantic Memory + Collections（见 `03`） |
| Cherry Studio | 多 Provider 管理 UI、本地知识库 | 设置→模型 / Workspace 知识库 |
| Yuxi | Harness 能力装配视图 | 设置→Agent Context，按 Agent 串联模型、知识库、Skill、Tool、MCP 与产物策略 |
| Coze | 插件市场分发 | 远期 Marketplace |
| AutoGen | Agent 间对话 | 远期 Multi-Agent Skill |
| Claude Code | Skill 概念、Plan 模式 | Skill 同名同义；Plan 模式作为 Meta-Agent 的一个 mode |
| n8n | 触发器机制 | 远期 "被定时/Webhook 触发的 Agent" |
| electron-builder 生态 | 自动更新、多平台打包 | 直接复用 |

## 6. 明确不抄的反例

| 反例 | 原因 |
| --- | --- |
| Web 优先 | 与"本地数据"目标冲突 |
| 强账号体系 | 单用户产品不需要 |
| 节点拖拽编辑器 | 学习成本与目标用户不匹配（非程序员） |
| Python 内核 | 单语言栈原则 |
| 让 LLM 自由生成 Agent 代码 | v0.x 稳定性优先（ADR-003） |
| 必装 Docker | 上手门槛太高 |
| 内置自家云服务 | 不做云 |

## 7. 远期可能竞合的方向

| 趋势 | Moyu 怎么应对 |
| --- | --- |
| OpenAI/Anthropic 推出自家 Agent Builder | 强化本地 + 多 Provider 中立性，做"中立平台"叙事 |
| OS 厂商内置 AI（macOS Intelligence / Win Copilot） | 主打"任务工件 + 可控编排"，与系统级助手互补 |
| MCP 生态爆发 | 抢做"最容易接入 MCP 的桌面平台" |
| 本地小模型（Phi/Qwen mini）能力跃升 | Tier 体系天然受益，无需重构 |
| Agent 市场监管/合规 | 单用户本地形态合规友好，可作为卖点 |
