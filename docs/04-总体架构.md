# 04 - 总体架构

> 本文是 Moyu 当前架构事实的主文档。历史 ADR、路线图和早期草图已经合并到这里；凡与源码冲突，以源码和本文的“当前实现”部分为准。

## 1. 当前定位

Moyu 是本地优先的 AI Agent 创建与运行平台。当前重点不是节点画布，而是：

- 通过 Meta-Agent 生成可审查的 Agent 文件夹
- 通过本地运行器执行 Agent
- 把 Run、Step、Artifact、Work 和 Message 留成本地证据
- 用 Workbench 把对话、产物、Trace 和设置上下文组织到一个工作台里

当前仓库仍是 `0.1.x` 原型阶段，已跑通“创建 Agent 草案 -> 安装 Agent -> dry-run / 生图运行 -> Trace / Artifact / Workbench 展示”的第一条闭环。

## 2. 架构分层

```text
┌────────────────────────────────────────────────────────────┐
│ Workbench UI                                                │
│ ui/workbench: 三栏任务会话、产物、Trace、设置中心             │
└──────────────────────────────┬─────────────────────────────┘
                               │ HTTP / static JSON
┌──────────────────────────────▼─────────────────────────────┐
│ Local UI Server                                              │
│ src/ui/server.ts: API 路由、静态文件、本地服务端口 fallback    │
└──────────────────────────────┬─────────────────────────────┘
                               │
┌──────────────────────────────▼─────────────────────────────┐
│ Core CLI / Services                                          │
│ src/cli.ts, src/agent, src/meta, src/runtime, src/settings    │
└──────────────────────────────┬─────────────────────────────┘
                               │
┌──────────────────────────────▼─────────────────────────────┐
│ Local Filesystem                                             │
│ agents/, traces/, artifacts/, moyu.config.json, .env          │
└────────────────────────────────────────────────────────────┘
```

当前没有 Electron 壳、独立后台进程、SQLite、向量库、MCP Server 或 sandbox worker。这些属于后续设计方向，不作为当前实现事实描述。

## 4. 本地文件布局

```text
moyu/
├── agents/                   # 已安装 Agent
├── artifacts/                # 本地运行产物，被 .gitignore 忽略
├── traces/                   # Run Trace，被 .gitignore 忽略
├── ui/workbench/             # 当前 Workbench 前端
├── ui/workbench-prototype/   # 旧路径兼容跳转入口
├── moyu.config.example.json  # Workspace 配置示例
└── docs/                     # 当前文档体系
```

Agent 物理目录使用 `__` 表示逻辑 ID 中的 `/`，例如：

```text
image-gen/prototype-v1 -> agents/image-gen__prototype-v1
```

## 5. 关键数据流

### 5.1 创建 Agent 草案

```text
用户 prompt
  -> CLI 或 Workbench API
  -> src/meta/create-agent.ts
  -> 推导 Agent spec
  -> 写入 artifacts/meta-agent-runs/<run_id>/<agent_folder>/
  -> validateAgentFolder
  -> 写 verification.trace.json 与 agent-draft.json
  -> RuntimeStore 写 traces/<run_id>/run.json
  -> WorkStore 写 artifacts/workbench/work-store.json
```

当前 Meta-Agent 是规则化生成，不调用 LLM。它会生成 `manifest.yaml`、`ui.yaml`、`README.md`、`.agentignore`、`prompts/system.md`、`agent.recipe.ts`、Skill 文件和 history 文件。

### 5.2 安装 Agent 草案

```text
run_id
  -> resolve draft manifest artifact
  -> validate draft folder
  -> copy draft into agents/<folder>
  -> validate installed folder
  -> update AgentDraft state
  -> update Work state
```

如果目标 Agent 已存在，默认不覆盖。Workbench / API 会提供：

- 创建新版本
- 查看文件差异摘要
- 放弃安装

### 5.3 运行 Agent

```text
agent_id + prompt
  -> findAgent
  -> resolve model roles
  -> RuntimeStore.createRun
  -> start image_gen step
  -> dry-run 跳过 provider 或调用 OpenAI-compatible 图片接口
  -> 注册 Artifact
  -> 写 Trace
  -> 写 Work / Message
```

当前只有生图 Agent 运行器，不是通用 workflow engine。

### 5.4 展示 Workbench

```text
npm run workbench:serve
  -> src/ui/server.ts
  -> /api/workbench 聚合 runs / artifacts / works / messages / agents / settings
  -> ui/workbench/src/app.js 渲染三栏工作台
```

`ui export-data` 可把同样的数据写入 `ui/workbench/public/data/workbench.json`，供静态预览读取。

## 6. 技术栈

当前实际技术栈：

- Node.js `>=20`
- TypeScript
- npm
- Commander
- Zod
- yaml
- Node built-in test runner
- 原生 HTTP server
- 原生 HTML / CSS / JavaScript Workbench 前端

早期文档中的 Electron、React、Tailwind、shadcn/ui、Zustand、better-sqlite3、LanceDB、isolated-vm、Docker 和 MCP SDK 仍是设计方向或候选项，不是当前仓库依赖。

## 7. 已实现能力

- 本地 Agent 发现、展示和校验
- 生图 Agent dry-run 和真实图片中转调用
- Run / Step / Artifact Trace JSON
- Run / Artifact CLI 查询与打开
- Meta-Agent 生成 Agent 草案
- Agent 草案安装、冲突检测、创建新版本和文件 diff 摘要
- Work / Message 本地 store
- Workbench 本地 API 与静态数据导出
- Settings 展示模型角色、知识库、Skill、Tool、MCP 和 Runtime 策略
- Workspace 模型角色配置读取
- Workspace 知识库配置读取
- Artifact -> Knowledge Base write-back 记录

## 8. 设计方向

以下能力保留为后续方向，当前不应在文档里写成已实现：

- Electron 桌面壳

- 通用 Recipe / workflow engine / step runner

- SQLite / 向量库持久化
- 真实知识库切片、嵌入和召回

- 模型动态路由器和 Monitor-Agent

目标形态和阶段任务见 [27 - 目标架构与大节点任务规划](./27-目标架构与大节点任务规划.md)。

## 9. 架构原则

1. 本地优先：Agent、Trace、Artifact、Work 和配置默认保存在本地。
2. 可审查：生成的 Agent 先作为草案，安装前必须能被用户检查。
3. 证据优先：运行过程留下 Trace，不靠 UI 状态猜测结果。
4. 角色优先：业务逻辑绑定 model role，不直接写死模型名。
5. 小步闭环：每个功能先跑通 CLI / API / Trace，再提升 UI 体验。
6. 当前事实优先：文档不能把计划当作已实现能力。
