# 26 - 当前缺陷与质量修复清单

> 来源：`23-v0.1-alpha验收记录.md`、`21-工程运行与状态.md`、当前实现观察。执行规则：**每次只修一个 bug / 一个质量问题闭环。**

## 使用方式

- 领取任务前，先复制 [bugfix-delivery-checklist.md](./checklists/bugfix-delivery-checklist.md)
- 一个 bug 对应一个 Issue
- 一个 bug 对应一个 Commit
- 修复后，把复现方式、验证结果和 commit hash 回写到本清单

---

## B-001 `file://` 静态预览模式验收不完整

- 状态：待修复 / 待验证
- 建议 scope：`workbench`
- 问题：当前虽有静态预览提示，但 `file://` 模式的完整人工验收尚未闭环
- 目标：
  - 明确所有受限动作的降级文案
  - 确保用户能稳定跳转到本地服务地址
- 回归重点：
  - 创建、安装、运行、打开 Trace、打开 Artifact 的提示一致
- 闭环 commit：

## B-002 安装冲突仅有结构化提示，没有明确操作闭环

- 状态：待修复
- 建议 scope：`meta`
- 问题：`install_conflict` 能返回结构化信息，但用户后续如何处理并不清晰
- 目标：
  - 补足版本更新 / 差异查看 / 放弃安装路径
  - 避免用户卡在“知道冲突了，但不知道下一步”
- 回归重点：
  - 重复安装、同 ID 草案安装、强制覆盖前二次确认
- 闭环 commit：

## B-003 Workbench 仍依赖原型文件结构，长期可维护性不足

- 状态：待修复
- 建议 scope：`frontend`
- 问题：当前页面逻辑集中在单文件原型中，后续功能继续堆叠会显著增加回归风险
- 目标：
  - 拆分视图与渲染逻辑
  - 把状态来源与 UI 表现解耦
- 回归重点：
  - Work 切换
  - Agent 选择
  - Inspector 与设置中心切换
- 闭环 commit：

## B-004 Work / Message 尚未持久化，导致会话恢复与追踪能力不足

- 状态：待修复
- 建议 scope：`runtime`
- 问题：当前 Work / Message 主要由原型态数据组织，无法支撑更长期的会话恢复与质量排查
- 目标：
  - 增加独立持久化模型
  - 支持恢复、检索、审计
- 回归重点：
  - 历史 Work 列表
  - 会话切换
  - 与 Run / Artifact 的关联关系
- 闭环 commit：

## B-005 模型 / 知识库 / Skill / MCP 目前多停留在文档与原型层

- 状态：待修复
- 建议 scope：`settings`
- 问题：概念已存在，但真实执行配置、验证与回归证据不足
- 目标：
  - 配置可读、可测、可追踪
  - 默认值、覆盖规则、回退策略显式化
- 回归重点：
  - 默认模型继承
  - 运行时覆盖
  - 配置缺失时的降级体验
- 闭环 commit：
