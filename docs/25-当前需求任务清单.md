# 25 - 当前需求任务清单

> 本清单只维护当前和后续仍有价值的 feature / docs / refactor 事项。已完成任务不再逐条展开，避免主文档变成历史流水账。

## 使用方式

- 领取任务前，先复制 [feature-delivery-checklist.md](./checklists/feature-delivery-checklist.md) 或直接在本清单补齐同等信息。
- 一个任务对应一个闭环。
- 完成后记录验证结果和 commit。
- 后续新任务必须绑定 [27 - 目标架构与大节点任务规划](./27-目标架构与大节点任务规划.md) 中的 P0-P6 节点。
- 如果任务不属于 P0-P6，先更新路线或补充架构决策，再领取实现。

## 路线执行顺序

当前目标路线以 `27` 为准。推荐执行顺序：

1. **P0 架构基线与任务系统**
   固化路线、任务清单、DoD、架构决策记录和阶段 demo 标准。
2. **P1 框架层完善**
   先把 Host/Harness 做稳：对话编排、Work 管理、运行时、沙盒文件系统、产物、插件、权限、中间件、异步 Worker 和 Trace。
3. **P2 Meta-Agent 生成可运行 Agent**
   Meta-Agent 生成 Agent contract、UI、Skill/Tool/MCP 装配、测试和沙盒 dry-run，安装前可审核。
4. **P3 Agent 对话机制**
   业务 Agent 支持 plan-first、追问、插话、流式执行、多产物交付、失败恢复、继续任务和 SubAgent handoff。
5. **P4 知识与文件能力**
   支持 PDF、DOC/DOCX、Office、HTML、表格、知识入库、RAG middleware 和文件权限策略。
6. **P5 插件生态**
   统一插件 manifest、安装审核、运行权限、本地开发、远程源、市场 UI 和审计。
7. **P6 产品化与多入口**
   桌面壳、多入口一致性、配置中心、数据迁移、备份导出、本地安全和更新机制。

- 建议 scope：`runtime`, `workbench`, `docs`
- 背景：F-075 已经让 Plan 进入 Trace 和对话流，但 Workbench 当前仍主要展示 WorkRecord 静态状态，缺少从 Run / Plan / Step 恢复出的生命周期、进度和最新运行摘要。
- 目标：建立 Work Manager v1 的只读生命周期投影，让 Work 可以从本地 Trace 恢复当前状态、最新 Run、Plan 状态和 Step 进度。
- 本次范围：
  - 新增 Work lifecycle/progress 投影类型和计算函数
  - Workbench `works` 暴露 lifecycle/progress/currentRunId
  - `/api/works` 返回带 lifecycle 的 Work summary
  - 旧 WorkStore 或旧 Trace 缺少 Plan 时保持兼容
  - 同步运行时文档和当前任务清单
- 非本次范围：
  - 不实现队列、后台 worker、取消、重试或真实恢复执行
  - 不改 WorkStore 持久化 schema
  - 不增加可写 Work 状态迁移 API
  - 不重做 Workbench 前端视觉
- 验收标准：
  - Workbench Work 列表能看到从 Run / Plan / Step 推导出的 lifecycle
  - `/api/works` 可返回同样的 lifecycle/progress 信息
  - stale WorkRecord 状态能被最新 Run 状态投影纠正
  - 旧 trace / fallback work 仍可正常展示
