# v0.1-alpha 闭环规格

> 目标：把 Moyu 从“能展示的 Workbench 原型”推进到“元智能体可以真实创建、审核、安装并运行 Agent 的最小闭环”。

## 1. 本阶段主线

v0.1-alpha 不追求完整桌面应用，也不先扩展大型前端工程。它只锁定一条平台主链路：

```text
用户通过对话提出 Agent 需求
→ 元智能体生成 Agent 草案
→ Workbench 展示草案文件树、预览和 Trace
→ 用户审核并安装
→ 新 Agent 出现在本地 Agents 列表
→ 新 Agent 可以被 CLI / Runtime 调用
→ Run / Step / Artifact 可追踪
```

## 2. 最小数据模型

### Work

`Work` 表示一次任务会话，不等于单次模型调用，也不等于单个产物。

最小字段：

- `id`：任务会话 ID
- `title`：任务标题
- `state`：`active | waiting_user | running | completed | archived`
- `createdAt`
- `updatedAt`

### Message

`Message` 表示 Work 中的对话、计划、进度和结果。

最小字段：

- `id`
- `workId`
- `runId`
- `role`：`user | agent | system`
- `kind`：`user_message | agent_message | plan | run_started | step_progress | artifact_created | checkpoint | error | summary`
- `content`
- `artifactIds`
- `createdAt`

### Run

`Run` 表示一次 Agent 或 Runtime 执行。

最小字段：

- `id`
- `workId`
- `agentId`
- `agentVersion`
- `recipeId`
- `state`：`queued | running | succeeded | failed | cancelled`
- `dryRun`
- `startedAt`
- `endedAt`
- `durationMs`
- `input`
- `reason`

### Step

`Step` 表示 Run 内部的可追踪步骤。

最小字段：

- `id`
- `runId`
- `name`
- `kind`：`llm | tool | skill | agent_call | control | user_checkpoint`
- `state`：`pending | running | succeeded | failed | skipped`
- `startedAt`
- `endedAt`
- `durationMs`
- `inputSummary`
- `outputSummary`
- `error`

### Artifact

`Artifact` 表示 Agent 或 Runtime 生成的可审查产物。

最小字段：

- `id`
- `runId`
- `producerStepId`
- `type`
- `role`：`primary | intermediate | report | log`
- `name`
- `path`
- `sizeBytes`
- `sha256`
- `createdAt`

### AgentDraft

`AgentDraft` 是元智能体创建 Agent 时的中间状态。v0.1-alpha 先以 `agent-draft.json` 记录最小持久化状态，并继续通过 `Run + Artifact` 暴露给 Workbench。

最小字段：

- `revision`
- `runId`
- `agentId`
- `draftPath`
- `targetPath`
- `state`：`drafted | validation_failed | installed | install_conflict`
- `validation`
- `createdAt`
- `updatedAt`
- `installedAt`
- `recordPath`：当前实现中由 Artifact `agent-draft.json` 承载
- `indexPath`：`artifacts/meta-agent-runs/agent-drafts.json`，用于按 `state` / `agentId` 查询草案

## 3. v0.1-alpha API

当前 Workbench 本地服务至少保留这些 API：

- `GET /api/health`
- `GET /api/workbench`
- `GET /api/agents`
- `GET /api/meta/agent-drafts`
- `GET /api/runs/:id`
- `GET /api/artifacts/:id`
- `GET /api/artifact-content?id=<artifact_id>`
- `POST /api/artifact/open`
- `POST /api/run/open-trace`
- `POST /api/meta/create-agent`
- `POST /api/meta/install-agent`
- `POST /api/agent/run`

## 4. Workbench 验收标准

- [x] 左侧 Agents 列表来自真实 `agents/` 目录，而不是静态假数据。
- [x] 点击“确认创建”会真实调用 `POST /api/meta/create-agent`。
- [x] 元智能体默认生成一个未占用的 Agent ID，避免和已有 Agent 冲突。
- [x] 右侧产物树展示本次元智能体运行产生的真实文件。
- [x] 点击文件后可预览文本类文件内容。
- [x] 点击“安装 Agent”会真实复制草案到 `agents/`。
- [x] 安装成功后，新 Agent 出现在左侧 Agents 列表。
- [x] 端口占用时服务自动切换，并在终端输出真实地址。
- [x] 已安装 Agent 可以从 Workbench 直接 dry-run 运行。
- [x] 左侧 Work 列表可以按 Run 切换右侧 Trace / Artifact 上下文。
- [x] AgentDraft 具备最小持久化记录，并能在安装后标记为 `installed`。
- [x] 安装冲突会返回结构化信息，并将未安装草案标记为 `install_conflict`。
- [x] 在浏览器中完成一次本地服务人工点击验收，并记录 UI 修正项。

## 5. CLI 验收标准

元智能体创建草案：

```bash
npm run dev -- meta create-agent \
  --prompt "Create an image prototype Agent that supports raw prompts and saves traceable artifacts"
```

安装草案：

```bash
npm run dev -- meta install-agent --run <run_id>
```

验证新 Agent 出现：

```bash
npm run dev -- agent list
```

运行新 Agent：

```bash
npm run dev -- agent run <new_agent_id> \
  --prompt "a clean app dashboard" \
  --count 1 \
  --raw-prompt \
  --dry-run
```

查询运行和产物：

```bash
npm run dev -- run list
npm run dev -- artifact list --run <run_id>
```

## 6. 非目标

本阶段暂不做：

- Electron 桌面壳
- 账号系统和云同步
- 可视化节点画布
- 大规模插件市场
- 完整数据库迁移
- 多用户协作
