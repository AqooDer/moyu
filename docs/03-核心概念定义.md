# 03 - 核心概念定义

> 后续所有设计、代码、UI 文案统一使用本词表。新增概念前先在此登记。
> 撰写日期：2026-05-20

---

## 0. 命名总则

- **中英对照**：每个术语固定一个英文名（代码标识符）和一个中文名（UI 文案）。
- **避免缩写**：除业内通用缩写（如 LLM、MCP），其余一律全称。
- **避免同义词**："执行" / "运行" / "调用" 在本词表中各有专门含义，不可混用。

---

## 1. 顶层概念

| 英文 | 中文 | 一句话定义 | 别叫成 |
| --- | --- | --- | --- |
| **Platform / Moyu** | 平台 | 整个桌面应用本身 | "App" 仅指可执行文件 |
| **Workspace** | 工作区 | 单个用户的本地数据根目录（含 Agents/Tasks/Memory/配置） | "项目" |
| **Library** | 智能体库 | 当前 Workspace 内所有已安装的 Agent 集合 | "市场"（Marketplace 是远程的） |
| **Marketplace** | 智能体市场 | 远程的 Agent 分享/下载平台（远期） | 与 Library 区分 |

## 2. 智能体（Agent）家族

### 2.1 Agent（业务智能体）
**定义**：一个可被调用、能完成一类任务的实体。由 **Manifest** 描述，由 **Runtime** 执行。

**必备字段**（详见 `05-元智能体设计.md` 的 Manifest schema）：
- `id` / `name` / `description` / `version`
- `system_prompt`
- `skills[]` — 装配的技能
- `tools[]` — 可用工具（含 MCP）
- `models[]` — 允许使用的模型清单（按优先级排序）
- `memory_profile` — 记忆配置
- `sandbox_level` — 运行隔离级别
- `inputs_schema` / `outputs_schema` — 输入输出契约

### 2.2 Meta-Agent（元智能体）
**定义**：平台内置的特殊 Agent，**职责是产出另一个 Agent 的 Manifest**。通过多轮对话收集需求 → 生成草稿 → 校验 → 试运行 → 修正 → 入库。

**不是**：不是一个"自我复制"的 Agent。Meta-Agent 不会改写自己。

### 2.3 Monitor-Agent（监控智能体）
**定义**：平台内置的离线分析 Agent。**异步**消费 Run 日志，输出"模型路由规则建议"或"Agent Manifest 优化建议"。

**关键约束**：
- 不在请求热路径上工作（不会增加用户单次任务的延迟）
- 输出的建议默认进入"待审核"队列，由用户一键采纳或忽略

### 2.4 三类 Agent 关系图

```
       ┌──────────────┐    生成 Manifest
       │  Meta-Agent  │ ────────────────► ┌──────────┐
       └──────────────┘                   │  Agent   │ 用户调用
                                          │ (业务)   │ ◄────────
                                          └────┬─────┘
                                               │ 产生 Run 日志
                                               ▼
       ┌────────────────┐    优化建议       ┌──────────┐
       │ Monitor-Agent  │ ◄──── 读取 ─────  │ Run Logs │
       └────────┬───────┘                   └──────────┘
                │ 路由规则更新
                ▼
       ┌────────────────┐
       │ Model Router   │
       └────────────────┘
```

## 3. 能力构件

| 英文 | 中文 | 定义 | 粒度 | 示例 |
| --- | --- | --- | --- | --- |
| **Tool** | 工具 | 单一原子能力，通过函数签名暴露（含 MCP Tool） | 函数级 | `read_pdf(path)` |
| **Skill** | 技能 | 一段可复用的、组合多个 Tool 或 LLM 调用的能力片段 | 流程级 | `extract_bid_outline(pdf) → outline` |
| **Provider** | 模型供应商 | 对接某一家 LLM 的适配层 | 服务级 | `AnthropicProvider`, `OpenAIProvider` |
| **MCP Server** | MCP 服务端 | 实现 MCP 协议、对外暴露 Tools 的进程 | 进程级 | `mcp-server-filesystem` |

**Skill vs Tool 的区分原则**：
- Tool = 副作用清晰的单步操作，**不调用 LLM**。
- Skill = 可能包含一次或多次 LLM 调用 + 多个 Tool 调用的组合。
- 一个 Agent 通常装配 N 个 Skill + M 个 Tool。

---

## 4. 模型层

| 英文 | 中文 | 定义 |
| --- | --- | --- |
| **Model** | 模型 | 一个具体可调用的 LLM 实例标识，如 `claude-opus-4-7` |
| **Model Tier** | 模型档位 | 抽象档位：`tiny` / `small` / `medium` / `large` / `frontier` |
| **Provider** | 供应商 | 见上节 |
| **Router** | 路由器 | 纯代码模块，**每次调用前**根据规则选定一个 Model |
| **Routing Policy** | 路由策略 | Router 用的规则集（可由 Monitor-Agent 增量优化） |

**关键约束**：Agent Manifest 只声明 `model_tiers`（如 `[medium, large]`），具体 Model 由 Router 在运行时根据当前 Provider 可用性与 Policy 选定。这样换模型不用改 Manifest。

---

## 5. 记忆层

| 英文 | 中文 | 定义 | 存储 |
| --- | --- | --- | --- |
| **Working Memory** | 工作记忆 | 当前 Run 内的对话上下文 | 进程内 |
| **Episodic Memory** | 情景记忆 | 单个 Agent 跨 Run 的历史交互摘要 | SQLite |
| **Semantic Memory** | 语义记忆 | 向量化的知识片段（含文件、笔记） | LanceDB |
| **Shared Memory** | 共享记忆 | Workspace 级，多个 Agent 可读 | SQLite + LanceDB |

**关键约束**：所有记忆默认按 **Agent + Workspace** 双重隔离。Shared Memory 必须用户显式开启。

---

## 6. 执行层

| 英文 | 中文 | 定义 |
| --- | --- | --- |
| **Task** | 任务 | 用户的一次执行意图（如"写一份高速公路标书"） |
| **Run** | 运行实例 | Task 的一次具体执行；每次重试是新的 Run |
| **Step** | 步骤 | Run 内部的一次原子操作（LLM 调用 / Tool 调用 / Skill 调用） |
| **Trace** | 链路 | 一次 Run 内所有 Step 的有序记录（用于回放、调试） |
| **Artifact** | 产物 | Run 产出的文件（如 `.docx` 标书） |

**状态机**（Run）：
```
created → running → ( succeeded | failed | cancelled | paused → running … )
```

---

## 7. 隔离层

| 英文 | 中文 | 定义 |
| --- | --- | --- |
| **Sandbox** | 沙箱 | Agent 代码/Skill 脚本运行的隔离环境 |
| **Sandbox Level** | 沙箱级别 | `L0` 主进程 / `L1` worker + isolated-vm / `L2` Docker（详见 `06-运行时与沙箱.md`） |
| **Resource Quota** | 资源配额 | CPU 时间、内存、磁盘、网络、Token 上限 |
| **Capability** | 能力授权 | 沙箱内可访问的外部资源（FS 路径白名单、域名白名单等） |

## 8. 配置与协议

| 英文 | 中文 | 定义 |
| --- | --- | --- |
| **Manifest** | 清单 | Agent 的完整配置（YAML） |
| **Schema** | 模式 | 用 JSON Schema / Zod 描述的字段约束 |
| **MCP** | Model Context Protocol | Anthropic 主导的工具协议；本平台一等公民 |
| **BYO Key** | 自带密钥 | 用户在本地配置自己的 Provider API Key（默认模式） |
| **Recipe** | 配方 | Meta-Agent 内置的"标书 Agent"、"PPT Agent" 等模板，加速对话生成 |

## 9. 反例（防混淆）

| 错误说法 | 正确说法 | 原因 |
| --- | --- | --- |
| "调用一个 Skill" | "执行一个 Step，其类型为 Skill" | Step 是执行单位 |
| "Agent 在 Docker 里跑" | "Agent 的某个 Step 在 L2 Sandbox 里跑" | 隔离针对 Step，非 Agent 整体 |
| "Meta-Agent 写代码" | "Meta-Agent 产出 Manifest；Skill 脚本由用户或内置库提供" | 不让 LLM 自由写代码（v0.x） |
| "智能体之间通过 API 通信" | "Agent 之间通过 Shared Memory 或 Tool 调用通信" | 不引入额外协议 |
