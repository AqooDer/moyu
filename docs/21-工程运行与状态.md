```bash

```

查看 Agent：

```bash

npm run dev -- agent validate agents/image-gen__prototype-v1
```

运行 Agent dry-run：

```bash
npm run dev -- agent run image-gen/prototype-v1 \
  --prompt "a clean app dashboard" \
  --count 1 \
  --raw-prompt \
  --dry-run
```

```bash
npm run dev -- spike image-gen \
  --prompt "a clean app dashboard" \
  --count 1 \
  --raw-prompt
```

Meta-Agent 创建草案：

```bash
npm run dev -- meta create-agent \
  --prompt "创建一个生图原型 Agent"
```

Workbench 对话式创建：

```bash
npm run workbench:serve
```

打开服务打印的 Workbench 地址后，选择「元智能体」，在底部输入框描述要创建的 Agent。当前对话式创建流程：

1. 用户描述 Agent 的目标、输入、输出和需要调用的模型 / 工具 / MCP。
2. Meta-Agent 在 WorkStore 中记录对话，并在信息不足时追问。
3. 信息足够时，Meta-Agent 回复确认 checkpoint。
4. 用户回复「确认创建」后，系统调用 `createAgentWithMeta` 生成 Agent 草案、Trace 和验证记录。
5. 生成的 Run 会绑定到同一个 Work，会话可在 Workbench 左侧任务中继续查看。

## 6. 图片中转配置

真实生图需要 `.env`：

```bash
MOYU_IMAGE_PROVIDER_BASE_URL=...
MOYU_IMAGE_PROVIDER_API_KEY=...
MOYU_IMAGE_PROVIDER_MODEL=gpt-image-2
MOYU_IMAGE_RESPONSE_FORMAT=b64_json
```

说明：

- `.env` 和 `.env.*` 被 `.gitignore` 忽略。
- CLI 会加载 `.env`，并覆盖同名 shell 环境变量。
- `MOYU_IMAGE_PROVIDER_MODEL` 未设置时默认 `gpt-image-2`。
- `MOYU_IMAGE_RESPONSE_FORMAT=url` 时按 URL 处理；默认 `b64_json`。
- `gpt-image-*` 不发送 `response_format` 参数，避免部分 OpenAI-compatible 中转站不兼容。

## 7. Meta-Agent 大模型配置

`meta create-agent` 可以使用 OpenAI-compatible 对话模型先生成 Agent 规格，再进入本地草案写入、校验和安装审核流程。配置 `.env`：

```bash
MOYU_LLM_PROVIDER_BASE_URL=...
MOYU_LLM_PROVIDER_API_KEY=...
MOYU_LLM_PROVIDER_MODEL=gpt-4.1-mini
```

说明：

- `MOYU_LLM_PROVIDER_BASE_URL` 可填写 provider 根地址、`/v1` 地址或完整 `/v1/chat/completions` 地址。
- 未设置 `MOYU_LLM_PROVIDER_MODEL` 时默认 `gpt-4.1-mini`。
- 未配置或 provider 调用失败时，Meta-Agent 会回退到本地规则脚手架，并在 Trace 的 `spec-draft` step 记录 `fallback_reason`。
- API key 只从环境变量读取，不写入 `moyu.config.json`。

验收命令：

```bash
npm run dev -- meta create-agent \
  --prompt "Create a research notes organizer Agent"
```

运行后可通过 `npm run dev -- run show <run_id>` 查看 `spec-draft` 的 `source`、`model`、`provider` 和兜底原因。

## 10. 当前限制

- 只有生图 Agent 原型运行器，不是通用 Agent runtime。
- Meta-Agent 已支持单轮 LLM 规格草案，但还不是完整多轮需求澄清、规划、测试生成和自动修复流程。
- Workbench 前端仍有较多逻辑集中在 `app.js`。
- Settings 当前只读。
- 知识库没有真实切片、嵌入、索引和召回。
- Artifact write-back 只记录审核事件，不写入向量库。
- 没有 sandbox 隔离。
- 没有 Electron 桌面壳。
