## 3. 环境要求

- Node.js：`>=20`
- 包管理器：`npm`
- TypeScript：通过本项目 `devDependencies` 安装

初始化依赖：

```bash
npm install
```

## 4. 常用命令

查看 CLI 帮助：

```bash
npm run dev -- help
```

运行生图技术尖刺：

```bash
npm run dev -- spike image-gen --prompt "a clean app dashboard" --count 4
```

查看和校验 Agent：

```bash
npm run dev -- agent list
npm run dev -- agent show image-gen/prototype-v1
npm run dev -- agent validate agents/image-gen__prototype-v1
```

运行首个 Agent。加 `--dry-run` 时只生成 Trace 和计划，不会真实调用图片服务：

```bash
npm run dev -- agent run image-gen/prototype-v1 \
  --prompt "a clean app dashboard" \
  --count 1 \
  --raw-prompt \
  --dry-run
```

查询运行记录与产物：

```bash
npm run dev -- run list
npm run dev -- run show <run_id>
npm run dev -- artifact list
npm run dev -- artifact list --run <run_id>
npm run dev -- artifact show <artifact_id>
npm run dev -- artifact open <artifact_id>
```

导出 Workbench 原型数据：

```bash
npm run dev -- ui export-data
npm run prototype:export-data
```

启动 Workbench 原型：

```bash
npm run prototype:workbench
```

默认监听 `http://127.0.0.1:4177/ui/workbench-prototype/`。如果端口被占用，服务会自动切换到下一个可用端口，并在终端输出真实地址。

类型检查：

```bash
npm run typecheck
```

自动化测试：

```bash
npm test
```

构建：

```bash
npm run build
```

## 5. 图片中转配置

当前生图链路使用 OpenAI-compatible 图片协议，中转站模型默认按 `gpt-image-2` 验证。

`.env` 会被 CLI 自动加载，且已被 `.gitignore` 忽略。不要提交 `.env`、API Key、私密 base URL 或任何凭证文件。Workspace 模型角色与知识库配置可参考 `moyu.config.example.json`，复制为本地 `moyu.config.json` 后按需修改；`moyu.config.json` 同样被 `.gitignore` 忽略。

常用配置项：

```bash
MOYU_IMAGE_PROVIDER_BASE_URL=...
MOYU_IMAGE_PROVIDER_API_KEY=...
MOYU_IMAGE_PROVIDER_MODEL=gpt-image-2
```

模型角色优先级：

- Workspace 默认：`moyu.config.json` 的 `model_roles`
- Agent 覆盖：`manifest.yaml` 的 `routing.model_roles`
- 运行时覆盖：显式设置 `MOYU_IMAGE_PROVIDER_MODEL` 时覆盖生图角色模型，并在 Trace 记录 `fallbackReason=env_model_override`

知识库配置：

- Workspace 默认：`moyu.config.json` 的 `knowledge_bases`
- 支持字段：集合标题、状态、`embedding_role`、`chunk_strategy`、`connected_agents`、`sources`、`write_back`
- `write_back.allowed_artifact_types` 只声明哪些产物类型允许后续回流；真实切片、索引、审核写回仍由后续功能实现

实现约定：

- `gpt-image-*` 模型按 `b64_json` 返回处理。
- CLI 不会向 `gpt-image-*` 模型发送 `response_format`，避免部分 OpenAI-compatible 中转站报 `Unknown parameter: 'response_format'`。
- `response_format` 仅保留给 DALL·E 2/3 兼容场景。
- 本项目会让 `.env` 覆盖同名 shell 环境变量，避免终端中残留旧 Key 导致 401。

## 6. 当前实现状态

已完成：

- 根目录 README 已改为面向大众的项目介绍。
- 设计文档已迁移到 `docs/`，不再通过外部软链接组织。
- `spike image-gen` 已跑通过真实 PNG 生成。
- `agents/image-gen__prototype-v1` 已固化为首个本地 Agent。
- `agent list / show / validate / run` 可用。
- Runtime Trace 已拆分为 `Run / Step / Artifact`。
- 图片输出会注册为 Artifact，并记录路径、尺寸和 `sha256`。
- `run list / show` 与 `artifact list / show / open` 可用。
- 元智能体可以生成 Agent 草案，并通过审核动作安装到 `agents/`。
- Workbench 静态原型位于 `ui/workbench-prototype/`，默认中文，支持 English。
- `ui export-data` 可导出 Runtime 数据供 Workbench 展示。
- Workbench 本地服务已接入真实 Agents / Runs / Artifacts / Works / Messages 数据。
- Workbench 设置中心已具备独立 `/api/settings` 数据入口、`#settings/<section>` hash 路由和独立加载 / 空 / 失败 / 重试状态，可展示模型角色、知识库、Skill、Tool、MCP 与运行策略的默认结构。
- Settings 模型领域可读取 Workspace 默认模型角色配置，Agent 可通过 `routing.model_roles` 局部覆盖，Run Trace 会记录最终命中的模型角色、Provider、Model 与回退原因。
- Settings 知识库领域可读取 Workspace 知识库集合配置，Workbench Settings → Knowledge 会展示集合、嵌入角色、切片策略、连接 Agent、来源与允许回流产物类型。
- Workbench 支持 `POST /api/meta/create-agent`、`POST /api/meta/install-agent`、`POST /api/agent/run`。
- Workbench 支持 `GET /api/settings`、`GET /api/works`、`GET /api/messages`、`GET /api/agents`、`GET /api/meta/agent-drafts`、`GET /api/runs/:id`、`GET /api/artifacts/:id` 只读查询。
- Work / Conversation Message 已落到 `artifacts/workbench/work-store.json`，用于 Workbench 左侧任务会话和中间对话流恢复。
- 左侧 Work 列表可按 Run 切换右侧 Trace / Artifact 上下文。
- 左侧 Work 标题优先使用运行 prompt，避免同类运行难以区分。
- Workbench UI 已完成一轮 polish：顶部去重、Inspector 降噪、dry-run 无产物空态、composer 压缩。
- `file://` 静态打开时会显示静态预览提示，并引导打开本地服务地址。
- 已有最小自动化测试覆盖 Meta-Agent 创建 / 安装 / dry-run / Workbench Run 切换 / Workbench API。
- Meta-Agent 创建草案时会写入 `agent-draft.json`，并同步更新 `artifacts/meta-agent-runs/agent-drafts.json` 查询索引；安装成功后标记为 `installed`。
- Agent 安装冲突会返回结构化信息，并把未安装草案标记为 `install_conflict`。
